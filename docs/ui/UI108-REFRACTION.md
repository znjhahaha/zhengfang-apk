# UI108：按课程页修复文字色散合成

App 开发版本 1.0.108 / code 108，基线 `uipreview` 的 `6d725e42b07d49863e0a7ecbc2951b2f287ed2d6`。SDK 3.2.9、API 3 保持不变。本次是 App 内部绘制修复。

## 课程页对照与故障原因

课程页通过 `SystemSegmentedControl` 使用原有文字折射路径：材质底图与强调色文字先合成，再进行一次透镜折射及色散。成绩和插件中心的 UI107 路径却把透明文字作为第二个透镜叠在背景透镜上。

透明字形边缘的各波长采样包含大量零 RGB / 零 alpha 像素。API 31/32 的 GLES 色散将 RGB 按波长权重相加，alpha 却取七个采样的最大值：少量颜色也可能配上完整遮蔽度，产生偏黑的原色碎片。这与课程页对完整底图做色散的输入不同。API 33+ 原先还使用了不同于背景的独立文字光学路径。

截图中的胶囊可能处于切换中；单凭截图不能认定静止位置错误。带实际玻璃分支的 API33 软件布局检查未复现静止位置错误。本轮没有调整选中索引、滑块位置动画或胶囊宽度。

## 修改

- 保留 `SegmentLabelSource` 对实际 `TextLayoutResult`、自定义字体、局部坐标的复用，以及 6% 静态放大，不恢复旧的重复文字排版。
- API33+ 用 `SegmentRefractionSource` 将局部材质和强调色字形合成，交给原有指示器的单次折射与色散。
- API31/32 使用已有背景/文字分开缓存机制；文字通过 CPU 字形快照进入 overlay，完成合成后才上传到 GLES。原先对独立文字区域设置的 CPU overlay 标志并未作用于没有 overlaySource 的背景记录；本次正确走实际 overlay 路径。
- 删除第二个透明文字透镜及其锚点。原有背景、轮廓光、按压形变和色散参数保留；不通过关闭色散掩盖问题。
- 正常光学帧和等待期间的同步回退都包含文字，普通标签在相同胶囊轮廓内避让，防止原色文字再叠一次。玻璃关闭、高对比度和尚未取得文字布局时保留普通标签。
- 课程页、课表日期分段、103 下拉栏和成绩学期记忆保持原行为；未修改插件契约、SDK或网站。

## 验证边界

`SegmentRefractionSourceTest` 把生产采样输入重放到独立透明位图，检查浅深主题、尺寸/位置及文本变化后，文字为强调色、透明字形间隙已填入局部材质，原色黑字未混入。不能把已画好壁纸的整窗截图当作透明度验证，否则旧的透明文字层也会误通过。

`SegmentLensPlacementTest` 使用真实背景与玻璃组件分支、真实触摸，检查静止选中位置、尺寸改变与单一标签语义。API32 的首次尝试因 Robolectric 缺少 EGL sentinel（`EGL_NO_DISPLAY` 为 null）失败，没有计为通过；布局检查使用 API33，API32 的字形/材质输入与独立回退检查单独执行。

受限 JVM 测试的实测数量、编译结果和交付状态见 `UI108-ACCEPTANCE.md`。本地输入与几何验证不等于 GPU 色散输出验收。华为 API31、API32 和 Android17 的静止/按压/滑动色散、复杂壁纸、收起动画、字体及玻璃开关继续等待设备确认。
