# UI109：拖动后文字闪烁修复

基线：`uipreview` 的 `fb0578514003af38ef9ca9cd48b4ad77a7790e6b`（1.0.108测试包）。开发版本1.0.109/code109，SDK3.2.9、API3不变。

## 已复现的无效更新

Compose 在仅改变前景文字颜色时可复用同一 `MultiParagraph`，但返回包装着新颜色的 `TextLayoutResult`。UI108 使用整个结果对象判断字形变化，导致滑块颜色动画也反复增加字形版本、使折射文字快照失效，并主动清空 `hasBackground`。实际透镜绘制又把文字统一染为强调色，这些快照更新并没有改变应该采样的字形。

新增回归在API32和33上均先失败：30步颜色动画中的第一步就错误增加版本；断言确认段落排版对象未变。原始失败记录保留在 `ui109-reproduce`。

## 修改

- 字形更新比较实际段落身份、测量尺寸与局部位置。颜色包装对象变化不再失效；低于1/64像素的坐标计算噪声忽略。不同段落/字体、真实位置和尺寸变化仍重新捕获。
- 成绩和插件中心拖动期间保持已提交选择的字重，用户确认切换后再更新字重；光学形变和前景颜色继续跟随手势。
- 字形回调只通知文字快照失效，不再抢先写入“背景没有画出”。是否已有可用画面继续由绘制端负责。
- 旧系统的异步折射帧携带采样几何与字形版本。后台仅更新底图时，旧完成帧保留到新帧就绪；尺寸、窗口位置、祖先变换或字形版本不一致则拒绝复用。
- 帧保留策略仅在新的稳定文字分段路径启用。课表日期、旧选择器和其他调用方维持原策略。保留UI108的“文字与局部材质先合成后色散”，不重新使用透明文字单独色散，也不关闭放大或色散。

## 验证与边界

`SegmentLabelSourceTest` 检查颜色动画、浮点噪声、实际移动、文字/字体和尺寸变化。`SegmentLensPlacementTest` 使用API33实际玻璃分支与触摸：拖到旧字重阈值附近保持，松手回原项，再切换并等待100帧，要求字形版本停止变化，语义仍只有一份。

`GlassLensFrameIdentityTest` 模拟20次背景更新、异步帧等待与替换，验证兼容帧不会消失、完成帧不会成为无限渲染时钟，且不同字形、尺寸、位置和变换被拒绝。它与真实源码的帧复用判断和队列共用逻辑，但不创建EGL或代替GPU输出测试。

实际通过数与任务退出码见 `UI109-ACCEPTANCE.md`。最终GPU闪烁、手势流畅度和色散观感继续待华为API31、API32与Android17设备确认。
