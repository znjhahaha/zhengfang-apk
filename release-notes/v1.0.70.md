## notes

本次让 Android 12 / 12L 也有了真正的液态玻璃折射，此前这两个版本只有模糊。
折射：Android 12 与 12L 缺少系统的着色器接口，玻璃控件一直只能用模糊近似。现在改用 OpenGL 离屏渲染补上，按钮、圆钮、开关、分段控件、选择器、弹窗与底栏都能看到背景被边缘弯曲、圆角处泛出彩色。
色散：原先边缘那圈固定的蓝黄描边是画上去的，并非真实光学效果。现在换成按红橙黄绿青蓝紫七个波长分别采样再合成，颜色只在圆角附近出现，与 Android 13 及以上一致。
修复底栏指示器静止时的彩边：切换到课表、成绩、设置页后不滑动，选中的那颗胶囊边缘会出现青蓝或粉色的一圈。原因是静止状态本不该有折射，与官方库的取值对齐后已消除。
修复底栏指示器换页后内容错位：换页时指示器里透出的画面停留在上一页，且不滑动就不会更新。
Android 13 及以上：底栏选中胶囊在静止时不再折射，与官方库行为一致；其余部分观感不变。
性能：折射所需的底图只在内容变化、滚动中限频、以及滚动停下时重新采集，静止时不产生额外开销。

### API 31/32 的真折射

- **用离屏 OpenGL ES 2.0 补上缺失的着色器能力**：`RuntimeShader`（AGSL）是 API 33 的平台类且没有兼容库，因此库的 `lens()` 在 31/32 上第一行就 `return`，这两个版本此前只有模糊。GLSL ES 2.0 自 API 8 就有，所以改走离屏 GL：EGL pbuffer 上下文 + FBO 渲染 + `glReadPixels` 回读，再由 `DrawModifierNode` 上屏。着色器是 kyant `RoundedRectRefractionWithDispersion` 的逐行同式移植（SDF、解析梯度、`circleMap` 曲线、七波长权重表、`(cx*cy)/(hx*hy)` 位置调制、位移取负配朝外梯度实现朝内采样），不是另做一套效果。设计与踩过的坑见 `docs/glass-lens-api32.md`。
- **覆盖所有玻璃控件**，不只底栏：按钮与圆钮、芯片、开关、分段控件、选择器下拉、弹窗面板。
- **真色散替换伪造的彩边**：此前 31/32 走的是 `chromaticFringe`，即在边缘画一圈固定的蓝黄描边。现在由着色器按七个波长分别采样合成，可见的彩边来自相邻波长的权重差；三通道 ±push 做不出这个效果，那只是 RGB 错位。三个通道的权重各自和为 1，因此均匀场进 = 均匀场出，不会整体染色。
- **`hasRealLens` 与 `hasLensLook` 分开**：前者回答"平台有没有 AGSL"，只该用来门控 `lens()` 调用；后者回答"这个站点看起来有没有折射"。额外模糊、更低的表面透明度、缺失的描边这些**补偿**只因为"这台设备没有折射"才存在，判据必须换成后者，否则折射会叠在补偿之上。
- **底图按区域共享、渲染目标按元素独占**：底图上传一次约 5ms，是贵的那一头，所以挂在不随控件移动的祖先节点上，控件滑动时只改采样窗口。但 FBO 与输出位图必须每元素独占 —— 曾经两者在同一个类里，改成 App 级共享锚点后所有元素往同一个 FBO 提交、又都读同一张输出，每个元素画出来的是最后渲染完的那个元素的结果拉伸到自己尺寸（屏幕上是选择器胶囊里一条灰带，140 行像素逐行几乎相同）。
- **底图必须复现控件实际压着的画面**：AGSL 的输入由平台喂，GL 这边要手工重建。底栏指示器压着"模糊壁纸 + 轨道容器色 + 锐利 tint 文字"；成绩页芯片压着 `combined(壁纸, 顶栏玻璃层)`，无模糊无轨道色；弹窗与下拉走 `vibrancy → blur → lens`，那层模糊只能**烤进底图**，因为屏幕上的 blur 加在 `drawBackdrop` 建的图层里，而折射在它上游就画完了。抄邻居的配方会得到一张错的底图。
- **按需重拍底图**：内容变化立刻重拍，滚动期间限频 100ms 一次，滚动停下补一次，静止零开销。试过并放弃常驻 `HardwareRenderer` + `SurfaceTexture` 的零回读通路：中位 4.69ms、p90 15.99ms，反而更差，因为它按 vsync 节拍走。

### 修复

- **底栏指示器静止时的边缘彩边**：`NavIndicatorRefractionFloor` 曾是 `0.42`，即静止也保留四成折射，注释写着"凸起镜片感"并当成 API 33+ 的既有基线。查库源码后确认库的指示器是 `lens(10dp * pressProgress, 14dp * pressProgress)`，静止**恰好为 0**、没有任何下限。这个自造的下限在 31/32 上后果更重：那条路采模糊底图，页面的彩色内容被摊成大色斑，静止折射把色斑沿胶囊边缘挤一圈——课表、成绩、设置三页底部有彩色内容，所以只有它们看得见。改为 `0f` 后实测斜坡与位移在静止态均为 0（原 15.1 / 22.7），按下仍到 `amount=54.35 thick=36.17`。两条路读同一个常量，因此 API 33+ 的指示器静止态同样不再折射，与库一致。注意库的**轨道**是无条件 `lens(24dp, 24dp)`，静止是折射的，这一点未变。
- **底栏指示器换页后底图不更新**：换页重拍那段是死代码。`selectedTab` 是普通 `Int` 形参而非 snapshot state，`snapshotFlow { selectedTab }` 只会发出启动该 effect 时捕获的那个值，此后再不发出；而 effect 的 key 里也没有它，所以永不重启。实测点标签后 logcat 里一条重拍记录都没有。改为把 `selectedTab` 当 key，顺带获得"连续换页时前一次的延迟被取消"的语义。另外重拍要等入场动画（160ms）结束后再补一次，否则拍到的是动画中途那一帧。
- **弹窗面板整块消失**：折射路径下调用方的 `onDrawBackdrop` 会让掉正常的背景绘制（背景由折射负责画），所以一旦锚点没被 `Modifier.glassLensAnchor` 挂到节点上，折射一个像素都不画、背景也没人画。现在两张底图都会挂上，`failed` 改用 snapshot state 存（失败会触发重组、连模糊兜底一起切回去），并且锚点未挂载时会明确报错而不是静默出错。
- **弹窗内部出现巨大圆弧**：`lensCornerRadiusPx` 只认 `CornerBasedShape`，而弹窗用的是 kyant `RoundedRectangle`，于是回落到"短边一半"约 295px，SDF 退化成胶囊。补上 `RoundedRectangularShape.corners()` 分支（与库自己的 `lens()` 读同一个接口），并加了回归测试。

### 工程

- **移除临时诊断脚手架**：`GlassLensProbe` 及其全部调用点。它此前在 `MainActivity` 里无条件开启、没有 `BuildConfig.DEBUG` 守卫，若随版本发出去会让每台设备把屏幕快照 PNG 写进 `cacheDir`。
- **新增仪器测试**：`GlassLensRendererTest` 在真机/模拟器上验证离屏折射真的出图，覆盖形状外透明、边缘带位移、色散只在圆角、多元素共享一个 GL 上下文、释放其中一个不影响其余、以及高频提交不堆积。另三个用例记录探路阶段的结论：`Bitmap.createBitmap(Picture)` 可用、ES 2.0 离屏能跑复杂片元着色器、零回读通路更慢所以放弃。
- **新增文档** `docs/glass-lens-api32.md`：说明哪些是从库移植的、哪些是本项目自己写的，以及三个查了很久的坑（位移被自己 clamp 到库的 1/3、着色器里多画一份轮廓光、自造的静止折射下限）。
